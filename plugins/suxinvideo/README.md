# 速信影视CMS GoSuxin 插件

## GoSuxin 迁入版本（仅基础数据）

后台入口 `/suxinweb/suxinvideo/admin`，前台入口 `/suxinvideo/`。Go 导入路径已适配 GoSuxin 本地基础框架，沿用主程序登录与权限。原 CMS 项目和服务保持独立。

主后台菜单显示“影视CMS”，带摄像机图标，折叠侧栏时仍可点击图标打开；首页“快捷操作”也提供“影视CMS后台”入口。启动时补齐旧菜单的默认标题和图标，保留管理员自定义项。

插件市场显示“影视CMS”的安装状态，可卸载及重新安装。卸载即时关闭接口、前台和后台任务并隐藏菜单及首页快捷入口，保留数据库、权限、配置、文件和源码包；重新安装恢复使用，不重置基础配置或重新导入旧业务数据。安装状态在主程序重启后仍保留。

仅使用 `install.sql` 中的 48 张表及基础种子：36 个分类、32 个播放器、4 个模板、15 个采集接口、5 张默认 SVG 幻灯片和默认配置；不复制影片、会员、订单、评论、播放记录、直播频道、旧 APK、采集图片或私有登录资料。直播默认分组、配置档和 4 个停用订阅由首次启动创建。

默认关闭后台自动采集、直播刷新与 Node 来源引擎；首页使用本站分类、内容和默认幻灯，不自动读取远端影片轮播。`suxinvideo.backgroundEnabled: true` 可在主配置中启用后台任务，采集仍须在插件设置中开启。独立 Jellyfin 监听默认禁用，可通过 `suxinvideo.jellyfinAddress` 指定空闲监听地址。管理员可在后台手动管理内容与采集，初始化不会抓取业务数据。

本版支持独立运行插件。Release 中的 `suxinvideo-2.5.0-windows-amd64.zip`、`suxinvideo-2.5.0-linux-amd64.zip` 可直接上传到支持运行协议的宿主；后续安装、更新、卸载及重装不重新构建或重启宿主，沿用原后台、影视前台和 APP API 地址。更新会替换插件进程，影视长任务可能中断。

开发机运行 `python scripts/build-runtime-plugins.py --os linux --plugin suxinvideo --build-web` 生成运行包。当前编译来源是主线 `api/suxinvideo`、`internal/controller/suxinvideo`、相关 `internal` 模块、`web/src/views/suxinvideo` 和 `third_party/akiralereal-iptv`，独立入口为 `plugins/suxinvideo/cmd`。Release 对应源码包直接从该提交生成；`go/`、`vue/` 及 `build.py` 保留为历史迁移参考，不作为当前运行包的编译来源。

安装和部署见 [运行插件指南](../../docs/runtime-plugins.md)。以下版本说明保留源项目功能沿革，提及的历史频道和客户端不属于本次基础数据迁移。

## 2.3.38 果果剧库首页与二次元插播过滤

- 果果剧库模板单独使用 4KVM 首页的宽幅幻灯、最近更新、热播、排行及其它推荐板块；切换到其它模板继续采用原有首页配置。横幅与竖海报独立保存，不按同名标题借用其它影片的图片。
- 首页后台刷新并保留最后成功的缓存；首次无缓存时先显示已采集的 4KVM 影片。推荐链接进入本站详情或播放，未采入的影片只在点击时按现有身份校验和采集合并规则准备，保留管理员启用状态、会员和积分限制。
- 二次元插播只对经过视觉核对的视频分段及完整内容签名过滤；不按时间点或所有 discontinuity 标记删除。广告下载或校验失败时保留原分段，避免误删正片。烧录在正片画面中的水印和未知广告不属于已确认的分段过滤范围。

## 2.3.37 默认片源、手机续播及来源评分

- 普通分类直接加载小柒APP，其次小柒其它线路；短剧直接加载红果；动漫直接加载二次元，其次小柒APP及小柒其它线路。首选缺失或实际失败时才优选同一分集的其它线路，手动切线仍有效。
- 手机切到后台时冻结播放停滞检测，保留视频实例、清晰度和位置。回到前台先恢复原连接，经过前台实际进展检测仍失败时才有限重解析。浏览器往返缓存保留播放器，iOS 的 Chrome 和 Safari 优先使用浏览器支持的原生 HLS。
- 评分独立保存各采集源的真实数据，依次采用已启用的小柒、红果、其它来源；无有效评分显示“暂无评分”。采集更新及后台补源都会更新评分，密码、会员限制及手动资料不因此被覆盖。
- 按明确指定的同名和近似标题清单统一列表及可访问片源；保留原影片 ID、收藏、购买与观看记录。季数、剪辑版本及权益独立校验，自动续播不会跳到另一季。
- 手动评分回填：`go run ./plugins/suxinvideo/tools/refresh_source_scores --ids 2164,11850 --output data/tmp/score-review`，默认只读。原生来源零分回填支持 `python plugins/suxinvideo/tools/backfill_native_scores.py --output data/tmp/native-score-review`；增加 `--apply` 后写入，写入前保存私有备份，使用同一输出目录可从检查点恢复。

## 2.3.36 红果全量核对与同片合并

- 红果原始影片统一归入短剧，原有剧情、都市、玄幻等标签保留为题材。采集最终匹配使用完整片名及作品身份，保留季数；粗略标题索引不能作为合并依据。
- 红果分集必须全部属于当前剧集 ID。原始红果记录可按经过核实的同一 ID 重建本季线路；其它来源的线路、影片 ID、会员限制及观看记录保留。
- 其它片源与红果的同名短剧按双方独立信息核验后补源。年份、地区或红果剧集 ID 冲突时停止合并；短片名且缺少身份依据的条目保留待核实，不将所有同名作品视为同一部。
- 普通资源站返回“现代都市”等子分类时，仅在本地已有同名分类的完整祖先一致归属短剧后用于同片匹配。匹配副本归一化为短剧，原题材及配置保留；分类重名跨频道、断链或循环时不推断归属。
- 本地全库审计：`go run ./plugins/suxinvideo/tools/audit_hongguo`。默认只读，无后台接口的扫描条数限制，输出包含禁用影片的完整本地库存及候选报告。它不代表上游红果全部目录已采集或逐集播放已验证。
- 添加 `--apply --output data/tmp/自定义目录` 后，先生成私有备份，再在事务中核对影片、来源和分类是否变化，只更新已确认的分类及播放列表，不删除重复影片。原季修复须另外提供 `--repair-native <已独立核实的私有证据JSON>`；备份与诊断均不包含在开发 ZIP 中。

## 2.3.35 按频道优先选源

- 短剧优先检测红果，动漫及动漫子分类优先检测二次元。保持原有线路编号及分集身份；优先来源必须实际加载到可播放画面，失败或超时后继续在其他来源中优选。
- 手动点击线路保留所选来源；普通频道仍使用原有最快可播放线路规则。优选期间显示正在检测的来源及进度。
- 红果关键词搜索接入采集及后台同片补源，按作品身份核验后才合并分集；保留现有独立线路、影片记录及管理员启用状态。
- 明确标为“全集”或“全集完结”的单条短剧合集，从头进入时可优先播放红果第 1 集；原合集已有续播进度时继续原版本。红果首次启动失败可回到原合集从头播放，不将不同剪辑版本的播放时间混用。

## 2.3.34 播放器控件与全屏

- 四套主题使用同一套画面内播放器控件，进度条和功能栏叠加在画面底部，播放时自动隐藏，鼠标、触摸和键盘操作可唤出。移除原有常驻 44 像素底栏及移动端高度补偿；进入全屏后视频元素覆盖完整播放器视口，默认保留原片比例。
- 参照 4KVM 当前播放器的操作布局，提供播放/暂停、拖动进度、播放时间、音量、倍速、画面比例、实际清晰度、下一集、投屏、网页铺满和浏览器全屏。画中画仅在浏览器支持时提供；手机将次要设置集中到设置面板，保证全屏按钮留在屏幕内。
- 下一集只在当前分集存在后续集时显示。切换清晰度、换源和下一集仍使用原有解析、续播与预加载流程；全屏状态由稳定的播放器外框保留。

## 2.3.29 剧场版同片补源

修复原影片缺地区、剧场版在另一来源被粗分为“国产动漫”时无法补充片源的问题。地区先从原始采集源的既存远端编号核实；仍缺失时，只在启用来源的详情中，通过已保存的完整播放地址逐字匹配取得独立依据，不用新候选的地区信息证明其自身。题名、年份、类型和地址必须符合校验；原有有效地区不会覆盖，也不合并或删除另一条影片记录。

仅对完整题名相同且明确含“剧场版”的动画电影，在详情证明线路为完整单部正片时兼容来源的普通动漫分类。电视连续剧、第二集、上下篇、预告及不同年份仍保持独立。“第1集完结”在已确认的单部影片中与 HD、正片对齐；普通剧集的分集身份不改变。

补源任务优先检查小柒聚合源，给它最多 60 秒并按剩余线路分配检测时间，避免前几条慢源耗尽全部机会；整轮最多三分钟，持续反馈进度并保留已验证线路。匹配规则版本参与缓存标识，旧规则的完成或失败结果不会阻止升级后的重新检查。缺字段的小柒详情仅由同一远端编号、同题名且无冲突的列表资料补齐。

## 2.3.28 片源插播广告过滤

“系统设置 → 播放设置”增加“过滤片源插播广告”和“广告片段域名”。默认开启，普通 HLS 代理、小柒 APP 的签名媒体代理与内置下载代理使用同一规则；开关和域名配置保存后在下一次播放清单请求生效。原始采集地址、影片与文件保留，可以关闭过滤恢复源清单。

仅对完整点播清单中边界明确的广告插片或已知广告地址执行过滤。普通片段的时长、文件名中的 `1o`、正常 CDN 域名及独立的 `DISCONTINUITY` 不作为广告证据；直播、主清单和无法安全处理的加密、字节范围或不完整标记保留原文。广告域名按完整域名及子域名匹配，每行一条，最多 64 条，不接受 URL、IP 或通配符。

小柒 APP 影片 3023 的清单在约 40:01 插入了三个带成对 `CUE-OUT/CUE-IN` 标记的二维码推广片段，共约 14.87 秒。过滤时保留正片的密钥、初始化片段和必要的衔接状态，避免删片后无法续播。媒体清单响应中的 `X-Suxin-Ad-Segments` 和 `X-Suxin-Ad-Duration` 可用于检查实际删除数量及秒数，不包含原始签名或密钥。

《凡人修仙传》第 193 集猫眼线路另确认三次“开元棋牌”插片，共 39.6 秒；第 192 集使用同一个广告库。该源每次请求会改变插入位置，因此只匹配已核验的 `play.maoyanplay.top` 上 `/20260818/JMQDkGOL/hls/` 目录内 `9OG1QJKR.ts`、`Dgaf3EqV.ts`、`Nr4MRgx5.ts` 三个完整地址，不按集数、片头时长、整站域名或整个目录删除。相同域名下的正片仍保留。

二次元《仙逆剧场版 弑仙之战》（本地影片 2164、源站影片 64933）的“有广”线路已逐段解码核验：原清单约 09:57.320 至 10:07.686 的三个独立片段全部为 `818818.com` 广告，共 10.366 秒，前后均为完整正片。《仙逆》第 160 集又确认使用完全相同的三个广告文件内容，路径不同但完整 SHA256 和字节长度逐一相同。两组已确认的完整路径直接过滤，正常正片中大量切镜所带的 `DISCONTINUITY` 全部保留。

二次元原生代理还支持识别上述广告换目录、换文件名后的复用：精确三段时长仅用于定位完整候选块，必须全部三段的完整 SHA256 和长度匹配已核验广告后才删除。单清单最多检查两块、六段，全局最多并发三段，总超时四秒，单段最多 2 MiB；成功缓存 30 分钟、失败缓存一分钟，同候选并发请求合并检查。已确认路径不增加网络请求，普通片源也不增加检查。失败、超时、只有部分内容匹配或不支持的加密格式均保留原文；重新编码或烧录到正片画面的广告需要重新核验，不能据此宣称所有二次元影片无广告。

画面中已经压入的水印、字幕广告及与正片混在同一媒体片段里的广告不能靠清单过滤消除；未确认边界的片头不按固定秒数盲删。

## 2.3.27 自动优选完整检查与电影版本对齐

电影线路中的 `TC`、`HD`、`正片`及清晰度标签按完整电影匹配，自动优选可覆盖小柒红牛等不同标签的线路；电影的上/下部分、数字分集、预告及花絮仍保留各自身份。后台补充片源与首次播放使用同一规则。

优选不再受固定 12 秒总窗口限制：最多并发检测四条线路，每条默认拥有 12 秒的解析和媒体准备时间，总预算按候选数量计算，直到找到可播放画面或检查完全部候选。检测进度以中文显示，重复地址去重；本页已超时的线路不会反复阻塞剩余线路。优选超时只作为本页尝试记录，不写入全局片源故障。手动选择和离开页面会取消旧检测，重试按钮重新优选。

## 2.3.26 短剧下一集预加载与播放按钮

四套模板的播放器功能栏增加“下一集”，仅在当前集有可播放的相邻下一集时显示；结束自动播放、按钮和预加载共用分集判断，重复清晰度条目、末集、缺集及停用线路不会被误当成下一集。页面解析播放器也提供同样的下一集入口。

短剧及其子分类在当前集开始播放后，使用相同的解析与媒体代理预缓冲一个下一集。点击按钮或当前集结束时复用已就绪的播放器和缓冲；失败或尚未就绪则正常解析。预加载失败不切换当前集、不上报源失效；切集、切线、页面隐藏或离开时取消未使用的预加载。HLS 只预取开头约 8 秒，红果流使用暂停缓冲上限约 15 秒，缓存最多保留 5 分钟，不批量预加载整部剧。

模板使用当前 `sx_*` 影片和用户数据，以及现有图片代理、线路优选、清晰度切换、自动下一集和播放解析流程。观看历史、收藏、搜索建议、分集跳转和会员入口已接通。后台“模板管理”或“系统设置 → 站点信息”可以切换模板。升级添加模板记录时不覆盖现有主题设置及业务数据；果果剧库独立服务的下载、Emby 和账户后台不属于本次前台模板接入范围。

## 2.3.24 首页各板块的移动端列宽

三套模板的首页、分类及推荐列表使用可收缩的影片卡片，防止长影片名或海报的原始宽度撑大网格。电影、剧集、综艺、短剧等板块按同一规则填满可用宽度，卡片列宽不再因影片内容不同而变化。

## 2.3.21 4KVM 接入与原生播放恢复

沿用已配置的正式 `4kvm://site` 采集源，更新官网搜索、详情元数据、分集名称及默认线路解析。播放优先使用源站返回的主地址，备用地址只有在返回有效媒体时才采用，避免将 HTML 页面作为 HLS。4KVM 支持关键词搜索及同片补源；合并仍核对名称、年份、地区和类型，数据库保留稳定分集标识。不添加测试或示例采集源。

4KVM 的合集入口和每集播放页编号分别保存：`4kvm://影片编号?dataid=…&quality=…&chapter=章节编号`。采集按影片编号合并，解析按章节编号取得签名，避免其它分集被误判为另一部影片。旧无 `chapter` 标识仍可解析。

4KVM 的 PNG 包装视频分片经确认 TS 包结构后移除图片前缀；真实图片、AES 密钥及 Range 响应保持原样。对应图床请求不附带 Referer，避免上游拒绝媒体分片；后台检测采用同样的识别规则。

小柒、红果和 4KVM 播放过程中，原生会话失效或媒体中断会限次重新解析当前分集一次，保留播放位置；仍然失败后才尝试其它同集线路。解析和权限错误不会无限重试，播放解析响应禁止缓存。已加载本版本脚本的页面在服务重启后可通过这一流程取得新凭据；升级前已打开的页面需刷新，永久不可用的上游资源仍会明确报错。

`yqk/` 中当前提供的是小柒 Go 签名 SDK；4KVM 实现位于插件的 `internal/xiaoqiapp`，随源码和插件 ZIP 一并交付。

修复本地二进制媒体代理在 AES 密钥或视频末尾追加宿主 JSON 响应，以及 Range 响应混入状态文本的问题。播放失败后并行优选同一集的其他线路，并复用胜者的缓冲和观看进度。优选超时、取消及未选中的候选不会提交线路失效报告。

小柒线路播放报错时由服务器复查最多三集的实际清单、密钥、首片段和清晰度，任一可用则保留；两次独立复查确认失败且间隔至少一分钟，才为该影片隐藏三十分钟。网络超时和接口解析异常不计为确认失效，原始播放数据不删除。部分上游线路自身返回 403、404 或连接失败，系统会尝试其他可用线路。

## 2.3.17 打开影片自动补源

进入详情或播放页后，后台异步搜索已启用的苹果 CMS 资源站，只给当前影片补充或更新线路，不新增其它影片。页面先正常显示和播放已有线路，随后展示检测进度；新线路加入资源列表，正在播放的视频保留播放器、缓冲、集数和进度。没有可用线路时，发现同集可用资源后开始播放。会员或积分限制仍生效。

匹配要求片名、年份、地区及作品类型一致；原始采集源可凭已保存的资源 ID 核实缺失信息。不同季、特别篇、剧场版及同名短剧不混入正剧。只合并首集和最新集均通过清单、密钥及媒体分片检测的直连线路。停用源不搜索，网页解析及尚不支持关键词搜索的专用源不参加此自动补源。

后台“系统设置 → 站点信息”新增“进入影片自动补源”和检测间隔。默认开启，同片检测间隔为 360 分钟，可设置为 15 至 1440 分钟；无匹配结果或检测失败时保留十五分钟间隔。任务记录保存在 `sx_source_discovery`，同片重复访问复用任务与结果，同时最多执行两部影片、每部三个资源站，排队有上限。重新安装和卸载保留任务记录及影片数据。

## 2.3.16 分片错误重试

修正普通 HLS 播放过程中将非致命 HTTP 分片错误立即当作整条线路失效的问题。分片短暂返回 403、404 或 502 等错误时，保留当前播放器及缓冲，让 HLS 按原配置执行重试或清晰度回退；重试耗尽的致命错误仍会触发同集换线，二十秒实际进度不前进的检测继续生效。取消优选、可恢复错误和用户暂停不会提交线路失效报告。

开发库影片 47《除暴之路》原百度地址返回 403，核对名称、年份及地区后补充红牛、迅雷两条正片线路，原数据库记录先行备份。影片 2928 的猫眼/红牛及影片 2164 的猫眼清单前二十分片重新抽查均可访问；抽样可访问性不等同于整部影片永不发生源站错误。这些影片数据修复不进入初始安装 SQL。

## 2.3.15 进入播放页自动优选

三套主题进入播放页时，对当前集的可用直连及专用解析线路进行并发加载，优先采用浏览器最先达到可播放状态的线路，并复用已加载的播放器和缓冲内容。最多同时加载四条，单条超过六秒会释放位置给后续线路，优选阶段最多十二秒；后续播放失败继续按同集换线。网页解析线路保留手动选择与失败回退。这个结果反映当次网络下实际加载的情况，不代表整部影片始终最快。

优选过程显示中文进度和选中的线路。手动点击线路或剧集会取消本次优选，避免自动结果覆盖手动选择；未解锁的会员或积分影片不发起媒体加载。未选中的播放器及请求及时清理，取消或优选超时不会计入线路故障记录。

开发库影片 2928《绘梦婚礼》原来只有返回 403 的百度线路。本次核对片名、年份、地区后，补充猫眼和红牛两条十二集线路，保留原数据备份。该影片属于开发库修复，不写入插件初始化数据。

## 2.3.14 单部电影换线

确认属于电影类别（含独立的“动画片”分类）的影片，单项线路使用完整片名、`HD国语`、`正片` 或 `第01集` 等标签时，可识别为同一部正片并自动换线。电视剧继续按原有集号匹配，预告、花絮、上下部、合集和剪辑版等不归为同一正片；存在多项线路时，单项的第 1 集也不会直接当作全片。修复影片 2164 百度播放地址返回 403 后，无法匹配猫眼完整片名的问题；不修改源站地址或历史业务数据。

## 2.3.13 多片源播放排查与同集续播

播放页统一识别 `第1集`、`第01集`、`EP01` 等无附加限定的集号，自动换线、手动换线和下一集按同集标识处理；预告、上下集和不同季的标签保持独立。专用解析超时或播放中断时也尝试其它线路，并保留同集已播放的位置。播放链接新增 `line` 参数记录线路代码，仍兼容旧的数字 `source` 参数；专用播放会话也绑定线路代码，避免其它线路被隐藏后序号移动。

三套播放器移除对无扩展名地址追加 `/index.m3u8` 的猜测，保持签名地址完整；停滞判断以实际播放进度为准。媒体代理复用 CDN 连接、限制 TLS 握手时间，HLS 相对分片和密钥基于重定向后的地址解析，源站返回 HTML/JSON 错误页时明确报错。合并影片按实际来源过滤线路，补齐红果、4KVM 及已识别资源站的启停判断，并修复已确认的旧豆瓣 CDN 地址遗漏。

源项目于 2026-10-01 对 13 个采集源做过有限样本检测；该历史业务抽样记录不随本次基础数据迁移交付。采集、解析和媒体可用性仍取决于外部来源，管理员添加内容后需自行核对。

## 2.3.12 线路来源名称与失效复查

百度与豆瓣共用 `dbm3u8` 代码，前台现在按保留下来的实际播放地址显示来源名称。停用豆瓣时，百度地址显示“百度资源”；只有豆瓣地址的线路仍会被过滤。

普通直连 HLS/MP4 播放失败后，前台向服务器提交限时签名的复查请求。服务器只检查数据库里的地址，最多同时检查两条线路；每条线路抽查当前集及其它集（最多三集），检查 HLS 清单、密钥和媒体分片。两轮检查间隔至少 60 秒，两轮所有样本都失败才隐藏**该影片**的这条线路 30 分钟；任一集能访问就保留线路。播放器继续尝试同集的其它来源。

原始播放数据不会删除；隐藏到期或采集更新了地址后重新展示。解析网页和红果等专用解析线路暂不参加自动隐藏。复查结果保存在 `sx_vod_source_health`，包含失败轮数、隐藏截止时间及错误摘要；升级自动建表，重复安装和卸载保留数据。检测确认的是媒体可访问性，不能保证任意浏览器都能解码。

## 2.3.11 播放缓存与同源媒体代理

播放页禁用 HTML 缓存并更新播放器脚本资源版本。HLS 清单、密钥及分片经带签名的同源代理传输，适配开发机的 TUN 合成 DNS 与浏览器跨域限制；代理仍拒绝内网地址。媒体分片通过 GoFrame 响应缓冲区返回，防止宿主中间件在分片末尾追加 JSON；签名有效期覆盖长影片播放。宿主可运行 `start-suxinvideo-latest.ps1`，每次先编译最新 Go 源码再重启服务，并验证前台可用。

## 2.3.10 播放线路去重与网页入口识别

同一资源站的 `*yun` 网页播放入口与 `*m3u8` 线路指向相同分集时，前台仅展示 HLS 线路；网页入口单独存在时按网页播放器载入，不再当作 MP4 直链。失效 HLS 线路仍由播放器尝试切换到下一条可用线路。影片 507 的迅雷分片服务器当前超时，红牛 HLS 分片可正常获取。

## 2.3.9 停用采集源的前台可见性

前台播放列表读取采集源和播放器启用状态。停用豆瓣资源后，已有豆瓣播放地址不再展示；与百度或其他来源合并的影片仍保留可用线路。首页、分类、搜索、推荐、站点地图和 RSS 隐藏只有停用来源的影片。重新启用采集源后，其已有播放地址自动恢复，无需删除或重新采集影片。

## 2.3.8 同线路分集合并

影片采集与手动合并现在按集数识别同一线路的重复分集。上游更新播放地址时替换旧地址，保留其他线路，不再将同一集追加两次。小柒 APP 的动态签名和实时播放接入已在 2.3.18 补齐，见 `YQK_API_NOTES.md`。

## 2.3.7 站点名称与图标

后台“系统设置 → 站点信息”可设置网站名称、网站 Logo 和浏览器图标。Logo 与浏览器图标支持 PNG、JPEG、WebP 上传（不超过 2 MB、2048 × 2048 像素），也可填写 HTTPS 图片地址。上传的文件保存在宿主 `data/suxinvideo/branding/`，插件升级时应保留此目录。三套前台模板的页头均使用网站名称；未配置 Logo 时显示主题原有图形，未配置浏览器图标时使用主题自带图标。

## 2.3.6 重复分集展示

播放页同一线路内按分集名称合并资源按钮，并按集数排序。采集合并得到的不同播放地址仍作为该集的备用地址保留；旧播放链接中的原始分集序号仍可使用。

## 2.3.5 单档提示与换线分集对齐

HLS 清单只有一档时，播放器显示实际分辨率及“单档”提示；片源未给出更多媒体地址时不提供无效的切换项。自动换线和手动切换线路按分集名称匹配，避免不同线路集数不齐时跳到另一集；线路失效时在页面标明已切换同一集，若没有对应可用线路则显示错误。

## 2.3.4 播放清晰度切换

播放页会根据片源实际返回的清晰度提供切换：红果及 4KVM 使用源站提供的多个媒体地址，普通资源站的 HLS 多码率主清单由播放器提供“自动”和各档位。切换时保留当前播放位置；只有单档的影片不显示虚假的清晰度选项。加密媒体仍由服务端处理，浏览器仅收到限时播放凭据。

## 2.3.3 红果画报修复

红果采集封面使用 HEIC 格式。站点图片接口现将其转换为 JPEG 并缓存到本地，页面首次加载后会把已有影片的封面地址更新为本地缓存地址，避免签名过期；三套模板的影片卡片与详情页都使用该接口。再次采集时会刷新尚未本地化的红果签名封面，已本地化或手动设置的封面保留。

## 2.3.2 红果总时长与进度跳转

红果解析接口返回当前分集的实际时长。加密分片 MP4 由浏览器 MediaSource 缓冲播放，控制条显示固定总时长；拖动到未缓冲位置时，服务端从目标时间重新解密转码。缺少时长或不支持 MediaSource 的浏览器沿用原播放方式。

## 2.3.1 红果播放修复

修复播放器将本地 `/suxinvideo/native/stream` 和 `/suxinvideo/native/proxy` 地址误补为 `/index.m3u8` 的问题；播放页通过资源版本号更新播放器脚本缓存。

## 2.3.0 果果剧库片源

新增红果、4KVM、量子、无极、暴风、红牛、闪电和迅雷片源。非凡与百度沿用原有采集源。黄豆、黄果未加入采集源。新增片源默认不参加定时采集，管理员可在采集管理中逐个启用。红果与 4KVM 使用专用分类、详情和播放解析；其余使用苹果 CMS 采集接口。源站接口和媒体链接可能变更，后台会显示当前请求的错误原因。

红果加密媒体由服务端 FFmpeg 处理，密钥不发给浏览器；Windows 插件包包含对应 FFmpeg 和许可文件，其他系统需安装 FFmpeg 或设置 `SUXIN_FFMPEG`。片源代码取自本地 `D:\AI\果果剧库`，封装于插件的 `internal/xiaoqiapp`；CMS 只注册红果和 4KVM 的专用入口。

## 2.2.1 资源站分类

“拉取资源站分类”使用苹果 CMS 的 `ac=list` 接口。进入采集源后自动拉取分类与预览；页面显示加载状态、分类数量和接口错误，选择分类后自动刷新预览。已有采集权限在升级时补齐分类与预览授权。

## 2.2.0 前台与采集任务

- 三套模板首页顶部使用已启用的 `top` 幻灯作为背景；SuxinPro 在没有 `top` 时使用 `movie`，仍为空才采用影片推荐。非影片幻灯保留原跳转链接并显示“查看详情”。
- 前台使用原三套主题的布局和样式类，播放详情使用 SuxinPlayer，支持线路、剧集、续播、自动下一集、播放失败换源和会员限制；分类、搜索、专题、文章、账户和充值页面接入对应的 Go 业务路由。
- 采集从同步 HTTP 请求改为持久化任务。`POST /admin/suxinvideo/collect/auto` 或 `POST /admin/suxinvideo/collect/job/start` 返回任务编号，`GET /admin/suxinvideo/collect/job/status` 查看进度，`POST /admin/suxinvideo/collect/job/cancel` 请求停止。后台页面每 1.2 秒刷新，关闭页面后任务继续运行。计划任务与手动任务共用一个并发限制。
- 升级会创建 `sx_collect_job`，不会清除现有业务数据。旧的采集权限会映射到新增任务接口；采集速度保存值仍使用 `gentle/slow/normal/fast`，界面改为中文。

运行 `python plugins/suxinvideo/tools/test_collect_parallel.py`，在独立临时数据库验证跨页、单页、并发额度、同源拒绝、停止、失败隔离、旧任务恢复和同片合并。脚本测试后清理自己的临时数据库；当前数据库账号没有建库权限时，使用本机 MySQL 程序创建隔离的临时实例。普通 `go test ./...` 不连接开发数据库。
