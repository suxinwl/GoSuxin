# 小柒影视原生 Android

一个 Android Studio 工程，两个安装包：`com.xiaoqi.video`（手机、平板）和 `com.xiaoqi.video.tv`（TV）。最低 Android 6 / API 23，目标 API 36。全部浏览及播放页面为 Compose / Media3 原生实现。

## 工程

| 模块 | 职责 |
|---|---|
| app-mobile / app-tv | 启动、设备界面、系统全屏与画中画 |
| core:model | 站点、影片、直播频道、节目单／回看、线路、分集、授权与业务规则 |
| core:network | JSON API、HTTP、服务地址发现与本站证书信任 |
| core:data | 业务仓库、Room 进度、DataStore / Keystore 账号会话 |
| core:player | 单一播放器、MediaSession、点播续播／预加载、直播换源／续期及共用手势 |
| core:download | Media3 DownloadService、Wi-Fi 队列、离线授权 |
| core:cast | TV 配对和 WebSocket、jUPnP UDN / Android 传输、局域网媒体中继 |
| core:design | 深色品牌、海报、焦点与二维码 |
| feature:catalog / account / library | 共用业务与手机、平板、TV 原生页面 |
| feature:live | 直播分组、频道搜索／分页、节目单／回看及手机、平板、TV 原生播放页 |

默认服务为 `https://xq.suxinwl.com:8600/suxinvideo/app/v1/`。API 合同见插件目录的 `ANDROID_API.md` / OpenAPI 文档。安装包包含公开 CA 证书，不含私钥。Android 7／API 24 及以上使用系统 Network Security Config；Android 6／API 23 使用按主机限定的信任路径。两种路径均验证主机名和服务端证书有效期；ISRG Root X1 仅附加到 `xq.suxinwl.com` 和固定配置 IP `59.36.165.33`，本站私有 CA 仅用于本站域名，其它 HTTPS 地址使用系统信任。CA 资源缺失或损坏会明确报告初始化失败；API 23 仅在尝试私有 CA 回退时检查其有效期，过期私有 CA 不阻断有效公信链。公信证书正常续期无需更新 APP。

## 1.0.16 启动与播放流程优化

- 启动沿用已保存的服务地址，动态配置在后台刷新；同地址在实际验证后 6 小时内复用健康结果。正常启动不显示服务恢复横幅，首页连接失败时仍可检查及切换地址。手动检查强制验证，TLS 和账号隔离继续保留。
- 首页、栏目和站点信息的匿名请求不等待会员存储初始化；首页网络请求与缓存目录版本校验并行，晚到缓存不能覆盖新的首页或服务器明确的权限／政策拒绝。
- 海报点击直接进入原生播放器，立即显示影片标题。小柒精选的远端身份接入与详情读取合并在同一次打开流程；列表页不再先等待接入完成。已完成的焦点预取详情可直接复用，权限仍由播放接口实时检查。
- 快速完成的加载不闪现阻塞提示，耗时超过 350 毫秒仍显示当前真实阶段。短时详情缓存按账号、凭据和服务器隔离；评论、收藏和解锁后失效对应影片信息。
- 当前播放标题按线路、版本和稳定分集编号显示，不再把影片更新备注当成正在播放的集数。切换剧集解析时立即显示所选分集，更新状态单独标注。

## 1.0.15 游客账号校验修复

手机／平板与 TV 使用 `1.0.15`／`115`，沿用原包名和发行签名。1.0.14 游客详情中断的根因是仓库账号校验的 `Long` 编号与未指定类型的 `0` 比较：无账号时右侧被装箱为 `Int(0)`，误判“账号已切换”，在 HTTP 请求前取消详情。

详情和续播读取现在统一调用已测试的生产 `PlaybackAccess.requireCurrent(Long?)`，游客默认值明确为 `0L`；真实账号和服务切换继续拒绝旧结果。回归测试覆盖无账号校验、共享详情任务到匿名加载链，继续保留 1.0.14 的超时及重试行为。验证记录见 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 1.0.14 游客播放与加载恢复

手机／平板与 TV 使用 `1.0.14`／`114`，沿用原包名及发行签名。打开影片立即读取公开详情，游客不等待账号初始化或读取会员的本地续播数据库。游客详情及播放解析明确采用匿名请求；会员保留令牌刷新和观看授权。

影片详情与可选续播读取总预算为 40 秒；会员续播读取最多 1.5 秒，记录不可用时从默认分集开始。播放源解析另有 50 秒总预算。加载超时或依赖主动取消时结束动画并提供重试，返回列表或切换影片仍取消旧请求，迟到结果不能替换当前影片。账号及服务切换后的旧播放结果继续被拒绝。

`兰香如故` 的匿名详情与网页播放已验证；网页验证不代表 Android 真机验收。完整构建、签名和发布证据见 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 1.0.13 升级恢复与小柒精选

手机／平板与 TV 使用 `1.0.13`／`113`，沿用原包名及发行签名。1.0.11 APK 固定使用 `kf.szputy.com`，没有动态地址获取或手动地址设置。旧域名已不指向当前服务，且无法修改其 DNS，因此既有 1.0.11 安装需从本站下载同平台新版覆盖安装一次；不要卸载，覆盖安装保留应用数据。新版本使用新域名及经过验证的 JSON 服务地址。

更新检查独立于首页和登录。APK 按版本及 SHA256 缓存，校验包名、发行签名、公布大小和版本；授予安装权限后返回 APP 继续安装，不再重复下载。检查失败提供中文错误、重试和下载页入口。

为保持 Android 6／7 对本站和固定配置入口公信证书的支持，额外打包已核验指纹的官方 ISRG Root X1 公开证书，仅用于这两个精确主机。配置入口不使用本站私有 CA；系统信任始终优先，旧私有 CA 的有效期不会阻断有效公信链。不关闭域名或证书有效期验证，JSON 不能添加信任锚。兼容依据见 [Let's Encrypt 官方说明](https://letsencrypt.org/docs/certificate-compatibility/)。

频道页主分类下方新增“本站片库 / 小柒精选”。精选复用网页的小柒频道及专题，保留每行／每页设置、分页与下一页预加载；未收录影片仅在点击海报后解析并合并到本站，不让整页等待逐影片导入。小柒精选和本地目录缓存分开，未确定总页数的游标目录显示“第 n 页”。

首页连接失败可再次“检查服务地址”。配置地址通过匿名 HTTPS 和本站 `config` 接口验证后才允许“切换并重试”；播放、投屏及更新期间禁止切换，会话与缓存继续按服务器地址隔离。

## 1.0.12 服务地址与启动配置

手机／平板和 TV 版本均为 `1.0.12`／`112`，HTTPS 深链改用 `xq.suxinwl.com:8600`。API、图片、播放、直播、下载、更新和投屏使用当前服务地址；APK 更新地址必须与当前服务的 HTTPS 域名及端口一致。

启动时立即使用本地最后验证可用的服务地址；首次安装使用默认域名。公开配置在后台匿名获取，连接、读写各限 1 秒，单次请求限 2 秒，整个检查最多 4 秒，不延迟首页请求。配置分享页的密码提交仅允许原入口的 HTTPS 主机和端口，获取配置和服务探测都不发送会员 token。

配置为空、返回 HTML 提取页、JSON 格式错误、接口不匹配或 TLS／网络失败时保留已有地址。新地址通过匿名 `config` 接口探测后写入本地，显示“服务地址已更新，重新打开APP后生效”；下次冷启动应用新地址，正在播放或下载的进程继续使用本次启动的地址。账号会话、公共目录、观看进度及下载按服务地址隔离，原单站会话和下载只归属于默认站点。

配置文件结构为：

```json
{
  "schema": 1,
  "project": "xiaoqi-video",
  "base_url": "https://xq.suxinwl.com:8600",
  "api_path": "/suxinvideo/app/v1"
}
```

`base_url` 必须是 HTTPS 的完整源地址，不含账号、路径、查询参数或片段。其它域名或 IP 的服务需要系统可验证的证书；本站 CA 的额外信任不扩展到新主机。`schema`、`project` 和 `api_path` 必须与示例一致。

开发构建可通过环境变量 `XIAOQI_BOOTSTRAP_URL` 设置配置分享入口；缺省为 `https://59.36.165.33:8976/down/ib3c2v0LlIH4.json`。需要提取密码时设置 `XIAOQI_BOOTSTRAP_PASSWORD`，缺省为空；密码编译进 network 模块的 BuildConfig，不写入源码或本文档。修改入口或密码后需重新构建 APK；日后修改同一入口中的有效 `base_url` 无需改动源码。

## 首页、模板和播放入口

- 1.0.7 优化长片名：播放页普通和全屏顶栏超宽时慢速滚动，完整片名在影片信息区换行显示并可复制。手机海报标题固定两行，长按海报或首页轮播可查看、复制完整片名；短按继续直接播放。TV 海报只在遥控焦点停留时滚动，短标题保持静止。
- 1.0.6 修复频道实际仅返回 3 部的问题：请求参数构造器中使用明确的 `CatalogRequest.size`，避免被 `buildMap` 的字段数量遮蔽。设置为 3 列 × 10 行时，频道、翻页和预加载均请求 30 部；保留纵向滚动及其它容量设置。
- 首页独立于站点配置、栏目和更新检查加载；最近 10 分钟的本地快照先校验服务端目录版本，再展示及刷新。版本校验失败或屏蔽规则变化时放弃旧快照，请求失败显示重试。
- 顶栏“模板样式”提供“跟随网站”、Suxinlite、SuxinPro、Iqiyi、果果剧库。个人选择保存在 DataStore，重启及退出账号后保留。
- Suxinlite：浅色紫系、圆角卡片、紧凑推荐网格；SuxinPro：红色沉浸轮播及海报墙；Iqiyi：绿色推荐、海报与标题并排轮播；果果剧库：粉色轮播、邻页预览及热播推荐。手机和平板的海报数量按显示设置调整，TV 保留横向海报墙及热播榜单；分类和搜索同步采用各自配色、卡片比例、尺寸与间距，全部为原生组件。
- 首页、分类、搜索、片库、片单、深链及关联推荐点击后立即进入播放器，再加载详情及解析线路，不进入独立详情页。离开或快速切换会取消旧请求；历史记录匹配线路、影片版本和分集时续播，版本变化从当前版本第一集开始。
- 分类／搜索采用完整筛选条件的短期目录缓存、同请求合并和下一页预取；当前页优先，预取失败不影响当前列表。缓存页展示前校验可见性版本，避免后台屏蔽／下架后继续展示旧影片。
- 1.0.4 在首页、频道和搜索顶部提供网格图标“影片显示数量”。可选每行自动或 2～6 部，每页 6／8／10／12 行；手机默认自动 3 列 × 10 行，分类页每页 30 部，较宽屏幕自动增加列数，小屏幕按可用宽度收敛列数。两项设置保存在 DataStore，重启、旋转和退出账号后保留。
- 手机／平板四套首页的栏目海报采用可调整的纵向网格，按实际返回数据显示数量与“更多”；不再只能左右滑动查看一行。分类和搜索的筛选、海报及分页一起上下滚动，适配较矮的横屏视口。首页每个栏目仍使用实际推荐条数，完整分页列表从“更多”进入；TV 保留遥控器布局。
- 每页请求数量按实际列数 × 行数计算，调整数量时回到第一页；下一页及相邻频道预取使用同一数量，避免误用另一种分页容量的缓存。
- 收藏、影片简介、评论、会员及积分解锁保留在播放器内；需要登录时可返回账号页，登录后恢复当前影片。TV 返回列表按栏目及具体海报恢复焦点。

## 直播频道与节目回看（1.0.11）

- 1.0.11／111 新增原生“节目单”入口、正在播出／下一档信息及按日期查看节目。日期按服务端节目单时区显示，提供近七天、今天与明天的查询；有节目不代表可回看，只给服务器明确授权、实际已结束的节目提供操作。缺失节目单有说明与刷新，不阻断实时直播。四套配色、手机亮度／音量、横竖全屏和 TV 遥控器焦点保持复用。
- 直播接口支持游客及可撤销的会员身份。已登录时携带访问令牌，401 通过原账号刷新流程重试一次；游客不刷新，403 不转成匿名请求。登录、退出和切换账号后重新获取目录并重新授权当前播放，不继续使用上一身份的媒体会话。权限错误提供账号／会员入口，返回原频道或回看后重新授权。
- 新增 `GET live/epg?channel_id=…&date=YYYY-MM-DD` 与 `POST live/replay/resolve`，回看使用频道、节目、线路、`catchup/event_replay` 模式及独立 `live-replay` 媒体身份，复用 `live/renew` 和 HTTPS 会话媒体代理。只显示源站真实提供的回看，不生成空节目或假回看。
- 有限回看支持真实时长、拖动、前后十秒、播放／暂停、线路与实际清晰度、后台返回和过期重解析续播。失败最多重新连接同一节目及线路一次，仍失败提供重试／返回直播；不会自动切成其它节目。结束后停在末尾，可重播或返回实时直播。回看不写影片历史、不触发下载、积分解锁、影片补源或下一集；旋转仍使用进程内同一个播放器。
- 播放格式由服务端显式 `mime_type` 决定：HLS 使用独立无缓存 HLS 媒体源，HTTP-FLV／MP4 使用无缓存 progressive 媒体源，清晰度可继承主格式。opaque URL 不按文件后缀猜测。HTTP-FLV 不支持拖动，实时 FLV 的返回直播／后台恢复重新解析连接；只有可拖动的有限回看显示有效进度操作。媒体 401／403／404／410／451 停止自动恢复并显示权限或不可用原因。
- 默认赛事频道也可直接进入真实有限 `event_replay`，未知官方日期时使用独立 `event_id`，不虚构节目单；总时长、拖动、质量切换和后台恢复按有限播放处理，同赛事／线路只刷新一次，结束停留。赛事专用频道的“选择直播”打开频道面板，避免将同一个赛事回放误标为实时；节目单回看仍按精确节目 ID 验证。
- 本轮 122 项 JVM 通过（包含已有模块复用结果）；最终日志 `android/android-111-build-event-final.log` 耗时 1 分 26 秒。手机／TV Release、Lint 和新增节目单界面测试编译证据见 [ACCEPTANCE.md](ACCEPTANCE.md)。未发现在线 ADB 设备，未执行真实手机／TV、节目回看或 FLV 播放验收。源站覆盖、媒体编解码和节目回看是否可用仍由实际来源和设备决定。

- 手机保留首页、频道、搜索、我的片库、账号五项底部导航，在频道页切换“影视／直播”；首页提供直播入口。平板侧栏和 TV 顶栏增加独立“直播”。频道支持分组、关键词搜索与分页，点击直接进入原生直播播放器，沿用四套模板配色与字体。
- 1.0.10 修复“只出现分类、频道持续转圈”的首载死锁：原请求在结束加载前等待网格滚动，但加载分支并未挂载网格。现在请求完成由独立加载器发布，网格显示后才发起滚动；首载、空数据、重试、切分组及翻页均不依赖布局回调结束加载，旧请求也不能覆盖新分组状态。
- 使用 `live/groups`、`live/channels`、`live/resolve` 和 `live/renew`，游客只看到公开可访问内容，会员按服务器授权访问。普通频道列表不逐台请求线路；解析响应一次返回当前频道及候选线路。播放 URL 使用本站的会话代理地址，APP 不需要保存源站密钥或请求头。
- 直播与点播共用进程内同一个 ExoPlayer／MediaSession，使用独立的频道和线路编号。进入直播会停止点播与下一集预加载，离开只停止当前播放和直播续期，不释放全局实例。直播不写电影观看进度，不调用影片补源、积分解锁、下载或自动下一集。
- 1.0.9 修复直播复用离线缓存导致动态清单停留在旧窗口的问题。直播使用独立无缓存网络数据源，显式创建 HLS 媒体源；主播放和清晰度地址即使没有 `.m3u8` 后缀也按 HLS 处理。点播与离线下载继续使用原缓存。
- 退出／重新打开直播重置后台暂停状态。播放途中再次缓冲也会启动 35 秒连接监测，用户主动暂停不误判为超时。频道切换取消旧解析和线路详情请求；线路详情与解析并行，解析失败后仍可手动选择备用线路。超时及网络错误使用中文提示。
- 支持频道、线路及真实清晰度选择、播放／暂停和“返回直播”。首次及后台返回从实时直播位置开始，不将滑动窗口长度显示为视频总时长；窗口过期时重新定位直播边缘。直播会话在到期前续期，过期或续期失败重新解析当前线路。
- 后端解析 502、实际播放中断或首播 35 秒仍未就绪时，APP 先重新解析当前线路一次，仍失败才排除该线并尝试备用线路；每条备用线路也最多刷新一次。直播首片较大时保留这段连接预算，避免提前误切健康线路；该预算不改变点播流程。新频道、手动选线路或显式重试重新开始这一轮。候选耗尽、重复已排除编号或权限拒绝时停止自动循环，显示重试、选择线路和切换频道，不进入点播查找更多片源。
- 每频道最近成功线路保存在独立本地记录中，只在媒体已就绪或实际播放、且身份仍匹配时写入；下次进入优先该线。旧缓存线路已失效时回退自动选源一次，不缓存仅解析成功但未播放的失败线，也不占用影片进度记录。
- 手机／平板复用左侧亮度、右侧媒体音量手势，支持原生全屏及手动横竖切换；退出恢复原窗口亮度和方向。TV 提供遥控器播放控件、线路／频道／节目单面板和返回列表焦点。直播及节目回看不提供离线下载或投屏；1.0.10 及以前没有节目单／回看入口。
- 直播首页采用频道卡片、选中分组和独立分页；播放器的频道／线路面板分为两个标签，避免多条线路挤占换台区域。手机控制栏分成两行，保持播放、返回直播、全屏、频道、线路和清晰度入口可见。线路使用中文名称或“主线路／备用线路 N”，真实分辨率与本轮失败状态单独显示；未检测到分辨率时不伪造 720P／1080P。
- 1.0.10／110 两款原签名 Release 包构建成功；最终日志 `data/tmp/android-110-build-final.log` 耗时 1 分 4 秒。当前 106 项 JVM 测试全部通过，包括首载不依赖网格布局、空结果、失败重试、旧响应隔离与退出取消；Gradle 复用部分未改变模块的通过结果。Release Lint 均无错误，手机与 TV 界面测试仅完成编译。再次检查未发现在线 ADB 设备或本机运行中的雷电模拟器，未获得真实设备直播播放结果；发布信息、大小及签名证据详见 [ACCEPTANCE.md](ACCEPTANCE.md)。已安装 1.0.9 及更早版本的设备需升级 APP 才能使用频道首载修复。

## 构建

- JDK 17、Gradle 9.1.0、AGP 9.0.1（内置 Kotlin）、Compose 编译插件 2.2.10。
- 本机便携 SDK 为 `E:\AndroidDev\sdk`，`local.properties` 不进入源码交付。
- 其他机器安装 Android SDK 36 / Build Tools 36，设置 `ANDROID_HOME` 或本机 `local.properties`。
- 依赖集中锁定在 `gradle/libs.versions.toml` 和各模块 `gradle.lockfile`；API 23 兼容所需 Java 库启用核心库脱糖。

```powershell
.\gradlew.bat :app-mobile:assembleDebug :app-tv:assembleDebug
.\gradlew.bat testDebugUnitTest lintDebug
```

Release 使用环境变量 `XIAOQI_SIGN_STORE`、`XIAOQI_SIGN_STORE_PASSWORD`、`XIAOQI_SIGN_ALIAS`、`XIAOQI_SIGN_KEY_PASSWORD`。密钥应单独备份，不能放入项目 ZIP。

```powershell
.\gradlew.bat :app-mobile:assembleRelease :app-tv:assembleRelease
```

APK 分别位于 `app-mobile/build/outputs/apk/release/` 和 `app-tv/build/outputs/apk/release/`。以后升级必须沿用原签名。APP 下载更新时验证 SHA256、安装包包名和已安装签名，经用户确认交给 Android 安装器。

## 播放和离线

- 1.0.6 在主题根节点设置继承文字颜色，修复独立播放页的标题、简介等在深色背景上显示黑色的问题；状态栏和导航栏图标同步跟随深浅样式。
- 手机控制栏常驻播放／暂停、时长、下一集、全屏和更多；线路、真实清晰度、选集位于次行，倍速、字幕、投屏、画中画和快进／后退放入更多菜单。TV 保留遥控器控件。
- 可用线路耗尽后自动发起一次同影片、同版本、同分集补源，轮询服务器的实际进度；新增或更新可用线路后保留进度恢复。标题下展示资源状态与“查找更多片源”，错误框也使用该操作；同一任务不能重复并发。权限拒绝、下架或离线不补源，补源不能绕过观看授权。源站仍可能没有可播放内容。
- 解析失败时以正在请求的分集身份为准，不能用上一集残留描述恢复；成功解析后归一化为实际线路／版本／分集。用户切换影片、分集或账号时停止旧的补源恢复，避免跳回上一集。
- 复用服务端分类优先源和权限规则，使用稳定线路、版本、分集标识。
- 普通栏目先小柒；短剧先红果；动漫先二次元。失败后查找同分集其它线路。
- Activity / 旋转复用进程内播放器。后台默认暂停，手动画中画继续播放。
- 手机／平板的视频区域左侧上下滑动调整窗口亮度，右侧调整媒体音量，上滑增加、下滑降低。手势超过触摸阈值才生效，底部进度条及按钮保持原操作；亮度离开播放页恢复，音量遵循系统媒体音量。
- 全屏顶部有“切换横屏／切换竖屏”。自动方向按实际视频尺寸选择；尚未取得尺寸的短剧先采用竖屏。手动选择在换清晰度及下一集时保留，退出全屏恢复原方向，视频保持 FIT 避免裁切。TV 保持遥控横向布局，画中画不响应亮度／音量滑动。
- Android 16 大屏允许方向限制的兼容属性仅用于手机／平板播放 Activity；多窗口及厂商系统仍可能由系统决定实际方向。参考 [Android 16 方向变化说明](https://developer.android.com/about/versions/16/behavior-changes-16)。
- 短剧只预解析并缓冲下一集，保持最多一个预加载实例。
- 下载并发 2，默认非计费网络。Media3 负责后台任务、恢复和分片缓存。
- 下载身份包含账号、影片、线路、版本、分集与清晰度；续期保留版本，版本改变时提示重新下载。
- 离线播放仅允许当前账号，授权最长 7 天。联网时重新验证服务器权益；完全断网时按已签发授权有效期判断。这里采用应用私有缓存与授权门禁，不提供硬件 DRM 的防复制保证。
- 红果经服务端完整分段 HLS 提供拖动和总时长；二次元经过现有广告过滤代理。

## 投屏

- 在 TV 账号页面生成配对码，在手机账号页面输入并确认。
- 自研 TV 直接获取自己的播放授权；手机发出播放、暂停、拖动、换集和清晰度命令。
- DLNA 发现限定局域网，先读取设备能力；不接受 HLS 的设备使用服务器准备的 H264 / AAC MP4。
- 媒体中继绑定局域网接口、随机能力路径，并限定所选电视地址。仅转发已登记的媒体资源，转发 Range；停止投屏立即关闭。
- 投屏前台服务保留中继，通知提供结束投屏入口。
